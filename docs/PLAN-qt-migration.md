# HotKey v2 迁移与实施计划（Tk → PySide6）

> 状态：可用版本完成 · M0–M5 已交付（2026-10-22）
> 已定决策：GUI 用 PySide6，界面用 Qt Designer 可编辑的 `.ui` 文件

## 1. 决策记录

| 项 | 决策 | 理由 |
|---|---|---|
| GUI 框架 | PySide6-Essentials 6.12（LGPL-3.0） | 项目是 MIT，PyQt6 的 GPL/商业授权与之冲突；Essentials 已含 Widgets/uic/Designer，体积约为完整包三分之一 |
| 界面来源 | `.ui`（Designer 编辑）+ `pyside6-uic` 生成 Python | 改版可拖拽；生成物是普通 `.py`，打包无额外数据依赖 |
| Python | 现有 3.14.2（已验证） | PySide6 6.12 是 `cp310-abi3` 轮子；PyInstaller 6.22.3 实测可打包并运行 |
| 执行模型 | 单 worker 线程 + 队列 | 热键钩子线程绝不执行用户代码 |
| 热键后端 | `keyboard`，包在 `HotkeyBackend` 接口后 | 先对齐现状；原生 `RegisterHotKey` 作为可替换实现，不在 v2 范围 |
| 编辑器 | 纯文本 + **整段编译** | 修掉循环/条件语句失效；积木编辑器留到 v3 |
| 数据 | 内部 v2（UUID + 整段 script），兼容读取 v1 | 消除下标 bug；老 JSON 仍可导入 |
| 打包 | PyInstaller **onedir** + DPI manifest | 更容易满足 LGPL 的可替换要求；实测 101 MB、冷启动约 1.5 s |

## 2. 范围

**v2 做**

- 热键的新增/修改/删除/启用禁用
- 组合键录制（Ctrl/Alt/Shift/Win）
- 语句面板拖拽 + 脚本编辑器（语法高亮、自动缩进）
- 启动/停止监听、托盘常驻、关窗到托盘、托盘退出
- 配置自动加载与保存、导入/导出 JSON
- 日志落盘到 `%APPDATA%\HotKey\logs\`
- 打包为可运行 exe

**v2 不做**

- 积木式块编辑器（v3 方向）
- 子进程隔离（只预留接口）
- 多语言、主题切换、云同步、脚本市场

## 4. `.ui` 工作流（本项目硬约束）

### 4.1 职责边界

- `.ui` 只描述：布局、控件、静态文本、`QAction`、快捷键、tab 顺序、尺寸策略
- 业务逻辑全部在 Python 控制类；`.ui` 里只连 `accept()` / `reject()` 这类标准槽，不连自定义方法
- 需要自定义行为的控件用「提升（Promote to）」：
  - `QPlainTextEdit` → `hotkey.ui.widgets.script_editor.ScriptEditor`
  - `QTreeWidget` → `hotkey.ui.widgets.statement_tree.StatementTree`
  - 提升时头文件填模块路径，`pyside6-uic` 会生成对应的 `import`
- 样式统一放 `theme.qss`，靠 `objectName` 或类名选择器定位；**不在 `.ui` 里写 styleSheet**
- Designer 里能配的全在 Designer 里配：`minimumSize`、`sizePolicy`、`shortcut`、`toolTip`、`statusTip`

### 4.2 objectName 约定（代码按名取，改名要同步）

| 文件 | objectName |
|---|---|
| main_window.ui | `centralSplitter`、`hotkeyTable`、`searchEdit`、`editorPanel`、`lblStatus`；actions：`actionNew` `actionImport` `actionExport` `actionSearch` `actionToggleEditor` `actionStart` `actionStop` `actionQuit` |
| editor_panel.ui | `statementTree`、`scriptEditor`、`btnCapturePos`、`btnCaptureColor`、`btnScreenSize`、`btnRunOnce`、`btnSaveScript`、`btnCloseEditor`、`lblEditing` |
| hotkey_dialog.ui | `keySequenceEdit`、`descriptionEdit`、`buttonBox` |
| preferences_dialog.ui | `chkMinimizeToTray`、`chkAutoStart`、`chkStartListeningOnLaunch`、`logLevelCombo`、`spinQueueLimit` |

### 4.3 生成与校验

```powershell
# 单个文件
.\.venv\Scripts\pyside6-uic.exe hotkey\ui\forms\main_window.ui -o hotkey\ui\generated\ui_main_window.py

# 全部
powershell -ExecutionPolicy Bypass -File tools\build_ui.ps1
```

- 生成物提交到 git：clone 后不装 Designer 也能跑
- 生成文件头写 `# AUTO-GENERATED by pyside6-uic from forms/xxx.ui — DO NOT EDIT`
- 测试中加一条「生成物一致性」：重新生成到临时目录并 diff，防止 `.ui` 与代码漂移
- Designer 入口：`.\.venv\Scripts\pyside6-designer.exe hotkey\ui\forms\main_window.ui`

### 4.4 加载方式

不用 `QUiLoader`（运行时加载对提升控件、资源和打包都不友好）。用生成的 `Ui_*` 类 + **组合**：

```python
class MainWindow(QMainWindow):
    def __init__(self, ...):
        super().__init__()
        self.ui = Ui_MainWindow()
        self.ui.setupUi(self)
        self.ui.actionNew.triggered.connect(self._on_new)
```

### 4.5 Designer 做不了、必须写代码的

- `QSystemTrayIcon` 与托盘菜单（托盘菜单在 `tray.py` 里建）
- `QAbstractTableModel` / `QSortFilterProxyModel`
- `QSyntaxHighlighter`
- 拖放 MIME 与「落到光标处」的插入逻辑
- 快捷键冲突检测、录制时屏蔽系统 Win 组合键
- 窗口几何持久化（`saveGeometry` / `restoreGeometry`）

## 5. 数据模型与存储

```python
@dataclass
class HotKey:
    id: str              # uuid4().hex，稳定标识
    key: str             # 规范化后的组合键，如 "ctrl+shift+a"
    description: str
    script: str          # 整段脚本
    enabled: bool = True
```

v2 文件格式：

```json
{
  "version": 2,
  "hotkeys": [
    {
      "id": "3f2c9a...",
      "key": "ctrl+shift+a",
      "description": "弹出提示",
      "script": "pyautogui.alert('Hello')",
      "enabled": true
    }
  ]
}
```

迁移规则（v1 → v2）：

- v1 顶层是数组，条目 `{key, description, code: [行]}` → `script = "\n".join(code)`
- 缺 `id` 补 `uuid4().hex`
- 重复 `key`：保留第一条，其余置 `enabled=false`，UI 上明确提示（不静默丢弃）
- 空 `key` 或非字符串：跳过并汇总提示

存储行为：

- 路径：`%APPDATA%\HotKey\hotkeys.json`；`--portable` 时用程序目录
- 写入：`.tmp` + `os.replace`，并保留一份 `hotkeys.json.bak`
- 自动保存：编辑防抖 800ms + 退出时再存一次
- 导入/导出复用同一格式（v2），导入兼容 v1

## 6. 核心接口

```python
# core/storage.py
def load(path: Path) -> list[HotKey]
def save(path: Path, entries: list[HotKey]) -> None
def import_file(path: Path) -> list[HotKey]      # 含迁移与校验

# core/validator.py
def validate(script: str) -> list[Issue]         # 整段脚本一次 AST
def build_namespace() -> dict                    # 与白名单同源

# core/runner.py
class ScriptRunner(QObject):
    started  = Signal(str)                       # hotkey_id
    finished = Signal(str, bool, str)            # id, ok, error
    def submit(self, hotkey_id: str, script: str) -> None
    def shutdown(self, wait_seconds: float = 2.0) -> None

# core/hotkey_service.py
class HotkeyService(QObject):
    triggered = Signal(str)                      # hotkey_id
    failed    = Signal(str, str)                 # key, reason
    def start(self, entries: list[HotKey]) -> None
    def stop(self) -> None
    def reload(self, entries: list[HotKey]) -> None

# core/keymap.py
def qt_to_keyboard(seq: str) -> str | None        # "Ctrl+Shift+A" -> "ctrl+shift+a"
def keyboard_to_qt(key: str) -> str
```

## 7. 生命周期与线程

```
启动：QApplication -> 单实例检查 -> storage.load -> HotKeyTableModel
      -> MainWindow(setupUi) -> 托盘 -> 可选自动开始监听

触发：keyboard 钩子线程 -> service.triggered.emit(id)
      （跨线程自动排队）-> 主线程收到 -> runner.submit(id, script)
      -> worker 线程执行 -> finished 信号 -> 状态栏/托盘提示

退出：service.stop() -> runner.shutdown() -> tray.hide() -> app.quit()
```

要点：

- 钩子回调里只做 `emit`，任何情况下不碰 QWidget
- worker 线程串行执行，天然避免两个热键同时操作鼠标
- 排队策略：队列上限可配（默认 5），超限丢弃并提示
- `closeEvent`：勾选「最小化到托盘」则 `ignore() + hide() + showMessage()`，否则走退出流程
- `setQuitOnLastWindowClosed(False)`，退出必须显式 `app.quit()`
- 单实例：`QLocalServer` 占用失败时激活已有窗口并退出

## 8. 语句目录与整段编译

- `catalog.Snippet`：`id / category / label / template / indent / cursor_offset`
- 块语句（`for` / `if`）模板带缩进与光标位：`for i in range(3):\n    ${cursor}`
- 编辑器插入时按当前行缩进对齐；`Return` 自动延续缩进，`Backspace` 在行首按级反缩进
- 执行：`compile(script, "<hotkey>", "exec")` 整段编译；失败时用 `SyntaxError.lineno` 定位并高亮到编辑器行
- 校验：整段 AST 一次；**导入时也校验**，执行前再校验一次（防线，不是唯一防线）
- 命名空间：`time`、`pyautogui`、`math`、`random`、`json`、`re`、`datetime` 全部注入，与白名单保持同一来源
- 无限循环：线程版无法安全中断，文档标注为已知限制；子进程版用超时 + kill 解决

## 11. 风险

| 风险 | 影响 | 对策 |
|---|---|---|
| Qt 6.12 + Python 3.14 打包异常 | 发不了版 | M0 先打空窗口；失败则退回 3.13 |
| Win 组合键录制会触发系统动作（Win+R 打开运行框） | 体验差 | 录制时提示；后续用 `keyboard` 的 suppress 钩子做「捕获模式」 |
| `keyboard` 维护停滞、部分场景要管理员 | 兼容性 | 接口隔离，必要时切原生 `RegisterHotKey` |
| 子进程化拖期 | 脚本卡死拖累 UI | v2 只留接口，单独排期 |
| `.ui` 与生成物漂移 | 运行与设计不一致 | 统一生成脚本 + 一致性测试 |
| QSS 依赖 objectName | 改名后样式失效 | objectName 表进文档，改名需同步检查 |
| 拖拽/高亮等自定义控件无法在 Designer 预览 | 调试成本 | 提升控件保持无参构造，逻辑放 `__init__` 之后 |

## 14. M0 完成记录（2026-10-22）

已在当前环境（Windows / Python 3.14.2）走通整条链路：

| 项 | 结果 |
|---|---|
| `pyside6-uic` 生成 | `main_window.ui` → `ui_main_window.py`，提升控件 `ScriptEditor` 正常导入 |
| 源码启动 | `python main.py --self-test` 退出码 0（offscreen） |
| 单元/界面测试 | `pytest` 4 passed（构建、提升控件、编辑面板显隐、生成物一致性） |
| PyInstaller | onedir 101 MB，`dist\HotKey\HotKey.exe --self-test` 退出码 0，耗时约 1.5 s |
| Qt Designer | `pyside6-designer.exe` 可启动，能打开 `hotkey/ui/forms/main_window.ui` |

M0 过程中确认的三个环境事实，后续阶段要沿用：

1. **用 `PySide6-Essentials` 而不是完整 `PySide6`**：Widgets / uic / Designer 都在
   Essentials 里，安装体积从约 250 MB 降到约 80 MB。
2. **系统临时目录对 Python 子进程不可写**（`%TEMP%` 抛 `PermissionError`），
   `tempfile.gettempdir()` 会回退到当前目录。因此 `pytest` 用
   `--basetemp=.pytest_tmp`，`build_ui.ps1 -Check` 的临时文件放在 `generated/` 内。
3. **`.ps1` 脚本只用 ASCII 文案**：Windows PowerShell 5.1 会按 ANSI 解析无 BOM 的
   UTF-8 脚本，中文字符串会导致解析错误。

已知遗留（不属于 M0）：`--self-test` 在窗口化 exe 上无法通过 PowerShell 管道观察退出码
（GUI 子系统进程不继承控制台），验证时用 `cmd /c start /wait ... & echo %ERRORLEVEL%`。

## 17. 积木式编辑器改版（2026-10-22）

界面从"自由文本编辑器"改为"Scratch 风格积木栏"：

- 右侧 `BlockTree` 不允许自由写脚本，只能从左侧拖入
- 每块积木是 `BlockRow`：彩色背景 + 中文文字 + **常驻参数输入框** + 删除按钮
- 参数输入框一直显示，不需要按空格打开；`number` 只接受数字，`text` 自动加引号
- 左侧最顶上增加「空」积木，拖入后直接在一行代码输入框里写 Python
- 把积木拖到 `重复执行 3 次` / `条件判断` 的中间，会成为子积木；`blocks.py` 递归生成缩进代码
- 积木目录、中文标签、参数类型、分类颜色、Python 模板全部放在
  `hotkey/core/catalog.json`；`catalog.py` 只负责加载、分段渲染和转义

数据模型升级到 v4：

```json
{"kind": "mouse_move_to", "text": "移动鼠标到（800, 600）",
 "params": {"x": "800", "y": "600"}, "children": []}
```

`script` 仍由积木生成后写入；v1~v3 的旧积木会按中文标签反解出参数（`parse_text`），
v1/v2 的纯脚本会迁移成一个「空」积木。

| 文件 | 作用 |
|---|---|
| `core/catalog.json` | 36 条积木的数据表（可编辑，不需改代码） |
| `core/catalog.py` | 加载 JSON、`segments()`、`render()`、`code_for_values()` |
| `core/blocks.py` | `Block` 树 -> Python，容器递归缩进 |
| `core/models.py` | `Block(kind, text, params, children)` |
| `ui/widgets/block_tree.py` | `BlockRow` 常驻输入框、拖放嵌套、删除 |

删除的旧文件：`ui/widgets/script_editor.py`、`ui/widgets/highlighter.py`。
坐标/颜色/尺寸按钮复制到剪贴板，直接粘到积木输入框里。

## 18. 画布式积木（2026-10-22）

用户要求"像编程猫一样，在大地图里拖拽积木"，因此在 v4 基础上重做编辑器：

- 顶层积木绝对定位，拖标题栏即可移动，按 20px 网格吸附

- 判断块改为「如果 {条件} 那么 … 否则 …」，一个积木两个槽位，
  第一个槽 -> `children`，第二个槽 -> `else_children`
- 积木位置随配置保存（`Block.x/y`），重新打开后回到原位
